# Разработка и запуск

## Требования

- Windows для полной версии с учётом активных программ.
- Node.js 22.12+; для автоматических проверок используется Node.js 22.
- pnpm 10 и Git.
- Интернет для установки Electron и использования Яндекс Карт.

## Установка

```powershell
git clone https://github.com/kartaamigo/Blaze.git
cd Blaze
pnpm install --frozen-lockfile
node node_modules/electron/install.js
pnpm check
pnpm start
```

Скрипт Electron скачивает бинарный файл официального runtime. Если pnpm сообщает о заблокированных install-скриптах, указанная отдельная команда устанавливает Electron для этого проекта. Не нужно отключать системную защиту.

Альтернативный запуск уже установленных зависимостей — `Start-Blaze.cmd`.

## Запускатель Windows

`Build-Launcher.ps1` использует компилятор .NET Framework и создаёт `Blaze.exe` в родительской папке. Существующий запускатель ожидает рядом папку **Blaze** с установленными зависимостями. При стандартном клонировании имя папки подходит.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Build-Launcher.ps1
```

Это небольшой запускатель локальной среды, а не автономный установщик. Бинарные сборки и `node_modules` не включены в Git.

## Предпросмотр

```powershell
pnpm preview
```

Основной интерфейс: `http://127.0.0.1:4173`.

Демонстрационные экраны: `http://127.0.0.1:4173/?preview=design`.

Галерея самостоятельных виджетов: `http://127.0.0.1:4173/widget-gallery.html`.

Сервер слушает только локальный адрес. Демонстрационный режим не сохраняет изменения пользовательского состояния. Предпросмотр содержит примеры, а не реальное время работы. Системные функции доступны только в Electron.

## Проверки

`pnpm check` выполняет проверку синтаксиса и поведенческие тесты `verify-behavior.cjs`. Workflow GitHub запускает те же проверки на Windows, с установкой зависимостей без загрузки Electron: тестам не требуется графическая среда.

Перед релизом вручную проверить создание и редактирование заметки, цвета, отдельные окна, перемещение, закрепление/открепление, закрытие и повторный запуск, общность таймера, календарь, часы, комментарии и доступность карты.

## Данные

В Windows каталог обычно находится в `%APPDATA%\blaze-workspace`. Пользовательская модель хранится в localStorage основного окна. Для переноса всех данных требуется продуманный экспорт обоих хранилищ; экспорт JSON настроек пока не заменяет полную резервную копию.

Главное окно при закрытии остаётся в трее. «Завершить Blaze» прекращает учёт и напоминания. Активный фокус после выхода не восстанавливается.

## Обновление документов

Рабочие функции описывайте как реализованные только после проверки. Макеты подписывайте как концепты, демонстрационные числа — как примеры. После изменения моделей, зависимостей или сценариев обновляйте отчёты и lockfile.
